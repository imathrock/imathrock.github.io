## Memory alignment
Memory in RISC V is aligned according to either the byte, halfword, word or doubleword. halfword is divisible by 2, word is by 4 and doubleword is by 8.

All instructions must be halfword aligned, since compressed instructions and full instructions can be intertwined so they must be halfword aligned. 

For load store of halfword and word, the alignment of the memory is implementation dependent. If they are not aligned then an exception can occur, causing a trap handler to run and terminate and report or align it, handle it and return. Or just let undefined behaviour happen, not advisable. 


## Conditional instructions
These are the instructions that affect the program counter register. 
for example:
```assembly
beq     rs1,rs2,imm12   # if rs1 ==  rs2, goto PC+imm12
```
These branch instructions are PC relative, as in it always goes to PC+imm12
Here are all the branch instructions:
```assembly
beq     rs1,rs2,imm12   # if rs1 ==  rs2, goto PC+imm12
bne     rs1,rs2,imm12   # if rs1 !=  rs2, goto PC+imm12
# signed comparisions
blt     rs1,rs2,imm12   # if rs1 <  rs2, goto PC+imm12. 
ble     rs1,rs2,imm12   # if rs1 <= rs2, goto PC+imm12. 
bgt     rs1,rs2,imm12   # if rs1 >  rs2, goto PC+imm12. 
bge     rs1,rs2,imm12   # if rs1 >= rs2, goto PC+imm12. 
# unsigned comparisions
bltu     rs1,rs2,imm12   # if rs1 <  rs2, goto PC+imm12. 
bleu     rs1,rs2,imm12   # if rs1 <= rs2, goto PC+imm12. 
bgtu     rs1,rs2,imm12   # if rs1 >  rs2, goto PC+imm12. 
bgeu     rs1,rs2,imm12   # if rs1 >= rs2, goto PC+imm12. 
```

### Misc instructions
```assembly
j       address     # jump to address
call    address     # ra = return address
ret                 # goto addr in ra
```
call jumps to the address and saves the return address in the ra register, when ret is called it jumps back to the address in ra. 
If ra is ever stored elsewhere then one can keep track of it, and restore it in ra as epilogue before ret is called. 

These are kind of psuedo-instructions as these can be replaced with a combination of other instructions. 

some more instructions:
```assembly
li      rd, imm     #load immediate : rd = value
la      rd, label   #load address:    rd = address
```
These are effectively the same instruction, they are probably different to make it easier for the assembler to run. 

### Syscall
```assembly
ecall
```
ecall is used to perform system calls. one must follow the calling conventions to setup arguments for the syscall functions. ecall reads the number in a7 and uses that number to invoke that particular syscall, it has no operand. 

```assembly
jal     rd,imm20
```
The jump and link instruction does the following: 
rd = return address
PC = PC + imm20 

```assembly
jalr    rd,imm12(rs1)
```
jump and link register
rd = return address
PC = PC + imm12

In cases where the jump is long, we change the PC in a different manner, we break it into the upper 20 bits and lower 20 bits. 
jump to a register with imm20 <<12 and then jump again with the remaining imm12. 

To simplify this there is another instruction:
```assembly
auipc   rd,imm20    # rd = PC+imm20
```
We can make long jumps PC relative. Benefit of PC relative instruction jumping is that it's address agnostic, you can copy and paste this code anywhere and it will still work. It's relocatable. 

Examples:
Long Jump, (PC-relative)
```assembly
auipc   t0, upper20
jalr    zero,lower12(t0)
```

Long call, (PC-relative)
```assembly
auipc   t0, upper20
jalr    ra,lower12(t0)
```
Difference is that we use the return address register. 


### Psuedo instructions
Psuedo instructions are instructions that are translated into lower level instructions. These are higher level assembly abstractions but underneath they simply repeat the base instructions. The following are all the psuedo instructions:

```assembly
ret                 # jalr zero,0(ra)
neg     rd,rs1      # sub   rd,zero,rs1
mov     rd,rs1      # addi  rd,rs1,0
not     rd,rs1      # xori  rd,rs1,-1
jr      reg         # jalr  zero,0(reg)
```

Some branch instructions are also psuedo, as shown:
```assembly
bgt     rs1,rs2,addr    # blt   rs2,rs1,addr
ble     rs1,rs2,addr    # bge   rs2,rs1,addr
bgtu    rs1,rs2,addr    # bltu   rs2,rs1,addr   unsigned
bleu    rs1,rs2,addr    # bgeu   rs2,rs1,addr   unsigned

# Assembler also provides these many zero comparision instructions
beqz    rs1,addr    # beq   rs1,zero,addr
bnez    rs1,addr    # bne   rs1,zero,addr
bltz    rs1,addr    # blt   rs1,zero,addr
blez    rs1,addr    # bge   zero,rs1,addr
bgtz    rs1,addr    # blt   zero,rs1,addr
bgez    rs1,addr    # bge   rs1,zero,addr
```
The li and la instructions are also psuedo instructions. They are emulated using the following:
```assembly
addi    rs1,zero,imm12    # if imm is 12 bits

lui     rs1,upper(imm20)
addi    rd,rd,imm12         # if 32 bits (>12 technically), splits into 2 instructions
```
The la, call and j are all psuedo instructions. 

## Assembler directives
```assembly
.byte   #integerExpr
.hword  #integerExpr
.half   #integerExpr
.word   #integerExpr
.dword  #integerExpr
.ascii  #"hello..", A string
.asciz  #"hello../0" A string with null terminator
.string # same as .asciz
.skip   #integerExpr, skips those many bytecounts
```
These are generally preceded by a label. 

The process is that a C file gets converted to assembly, the assembly file then gets converted to an executable. My LC3 project should show how assemblers work. 

One of the object files must have:
```assembly
.globl  _start
_start:  ...
```
_start is a privilaged name, it is the entry point for all executables. It's the first instruction ran that then calls main() in our C code. 

Some more assembler directives:
```assembly
.equ    symbol, value   # set's symbol to value which can be a variable or an address.
.set    symbol, value   # set's symbol to value which can be a variable or an address.

.align  integer # forces the data to align to memory boundaries, probably has syscalls.

.text       # code 
.data       # r/w data
.bss        # zero data, something like a calloc that is called when required.
.rodata     # not allowed, read only data segment. 
```

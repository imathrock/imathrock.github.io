# Architecture

Lets look at an example instruction:

```assembly
mylable:    add  x5, x7, x6
```

This line adds contents of x7 and x6 into x5. mylabel is a label that is identified using ":". opcode is "add" and the registers are operands. 

These registers can also be referred using a completely alternate naming convention like:
```assembly
- x0: zero
- x1: ra # return address
- x2: sp # stack pointer
- x3: gp # global pointer
- x4: tp # thread pointer
- x5: t0 # temporaries
```
and a lot more. We would use them interchangably. 

Looking at some registers in more detail:
- x0, zero. hardwired to always contain zero, done so because it's useful.
- ra, x1. The *call* instruction does not push the return address to the stack it just stores it in ra. The *ret* instruction simply jumps to the address in ra. It's beneficial because we do not waste time fetching from memory the return address, but like only beneficial in leaf calls. If it's nested then better store it on the stack. 
- sp, In some computers the stack pointer is a dedicated register but in risc V you can use any general purpose register. By convention its x2. 
- a0 - a7 are all argument registers, by convention functions return in a0. These are to be not changed during a function call unless it's a nested call. 
- t0 - t6 are scratch registers as in they are to be worked on by the function, these are caller saved, a called function might tamper with them
- s0 - s11 are similar to temp registers. These are callee saved, like if they're used then they must save the old values and then bring them back after being used.
- gp is the global pointer, it's a pointer where global or static variables are kept to make addressing easier.
- tp is a thread pointer, thread specific variables are kept there.
